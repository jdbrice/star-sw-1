One page so these are not rediscovered one at a time. Every item here is
deliberately NOT done yet, and the reason is the same in each case: a pure
rename or reformat colliding with real work is the worst kind of conflict to
resolve, because every hunk looks identical and the merge cannot tell which
side meant what. So they wait until the PRs that touch the same files are in.

Items are listed with their GATE. When a gate opens, do that item alone, in
one commit containing nothing else, so the diff is reviewable at a glance.

4. mm -> cm, Tier 3: the persistent classes
-------------------------------------------
    StFttPoint v4, StFttCluster v5, StFttRawHit v5, StMuFttPoint v3. NOT a
    cleanup -- a data format migration. Changing the UNITS of an existing
    persistent field is the nastiest schema change there is, because the bytes
    are identical and only the meaning moves, so ROOT cannot notice. Needs a
    ClassDef bump on each plus a read rule scaling by 0.1, or every existing
    MuDst and picoDst silently reads ten times wrong.
    GATE: schedule it WITH the retirement of StFttPointMaker, never as a tidy-
          up. StFttClusterPointMaker already writes cm, so that switch is when
          FTT point units change anyway -- one migration instead of two.
