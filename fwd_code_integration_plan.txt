PROPOSAL IN ONE PARAGRAPH

Much of the forward-upgrade development of the last two years is NOT in the STAR repository. 
It lives in Daniel Brandenburg's `dev` branch, plus work of Akio's in "akio202607" branch. 
We propose to land it as a sequence of small, independent pull requests against STAR Gitea, 
in a fixed order, rather than as one large merge. This document lists what exists, 
what it depends on.

1. THE SITUATION

  Daniel's dev vs the frozen STAR main:  394 commits, 140 code files, +15310 / -818.
  A patch-id comparison finds 392 of those 394 have no equivalent upstream, i.e. almost
  nothing was merged before the GitHub repository was frozen.

  Eight of Daniel's pull requests were still open at the freeze and are now unreachable
  as PRs: #569, #759, #796, #804, #810, #811, #815, #826. Every one of the branches
  still exists in jdbrice/star-sw-1, so nothing is lost; only the PR threads are.

  PR #826 alone is 125 of those 140 files and +12890 of the +15310 lines. It should not
  be re-proposed as one piece, and it does not need to be: it is a handful of Akio's
  commits that Daniel had already separated into PRs #13-#19 in his fork, so the smaller
  PRs already exist. See wave 5 below.

  Separately we have more recent work that has never been in PR against "dev": 
  16 new and 46 modified code files, mostly sTGC/FST alignment, the DB-driven 
  geometry path, and diagnostics in "akio202607" branch.

3. THE PLAN

  Ordering principle: schema first, because everything depends on it; then
  self-contained new packages, which nobody depends on; then the tracker core; then
  the wiring that drives all of it. Within a wave the PRs do not touch each other's
  files.

  A note on BFC options, which cut across several waves below. Every new maker needs a
  chain option before anyone can use it, so each maker should land WITH its own option
  rather than waiting for a separate options PR. Current state:
    StFttSimHitMaker        has no BFC option anywhere -- one has to be written
    StFstSlowSimMaker       option "fstSlowSim" exists only in akio202607
    StFttClusterPointMaker  option comes with #810
    fttSim / FcsTrackMatch / PicoVtxless   are what #759 adds

  WAVE 1 -- BFC options, recoverable verbatim from Daniel's branches
    #759  BFC options for FWD productions                      1 file,  +6
          NOTE: the "fttSim" option it adds names StFttFastSimulatorMaker, which does
          not exist in main, dev or akio202607. The FTT fast simulator is
          StFttFastSimMaker in package StFttSimMaker. Fix the name or the option will
          fail to load when used.
    #796  BFC chain options for FTT sim / FCS track match      1 file,  +6/-22
          NOTE: as it stands this branch also DELETES four production chain
          definitions (B2023b, P2023b, B2024b, pp2024b). Cherry-pick the additive
          part only.

  WAVE 2 -- all persistent schema, in one place, nothing else in it
    StFwdTrack track types kBLCVertexConstrained=4 and kFCSConstrained=5,
    StFwdTrackCollection ownership, StPicoFwdTrack fields, and #804 StMuFwdTrack
    ClassDef 3->4 with mTrackType (3 files, +11/-8). Wave 5 depends on this.
    #804 was listed separately before, but it is the same schema change seen from the
    MuDst side and the note below applies directly to it.

       Note : StMuFwdTrack's new StMuFwdTrackType enum stops at kForwardVertexConstrained=3.
       Correct against today's main, but mTrackType is copied straight from
       StFwdTrack::trackType(), so once kBLCVertexConstrained=4 and kFCSConstrained=5 land
       here, anything reading this enum mislabels them. Extend it in the same PR.

  WAVE 3 -- geometry and DB constants
    StFttDb: embed strip geometry instead of reading Row*.txt   14 files, +1868
    StFttDb: DB-geometry mode and switch (ours)   -- same file, so it follows the above
    StarDb/Geometry sTGC + FST survey tables      11 new files, independent of the rest
    StarVMC: sTGC zplane int -> float                            1 file,  +11/-2
          11 lines. `zplane` is declared int in StgmGeo1.xml, so the sTGC station z
          values are truncated to whole cm: the geometry is built at 312.8385 /
          330.8385 / 346.8385 / 364.8385 instead of the survey values, errors of
          +5.0 / +8.9 / -8.0 / -5.8 mm, and the station spacing is not even monotonic.
          Highest value per line in this document.

  WAVE 4 -- simulation: both slow sims are new and belong in the library
    StFttSimHitMaker                               2 files, +429   (in dev, not in main)
          Real-geometry FTT simulation:
          G2THIT -> StFttSimHitMaker -> StFttClusterMaker -> StFttClusterPointMaker.
          The FTT counterpart of the FST slow simulator; the existing
          StFttFastSimMaker does not exercise the real geometry or the clustering.
    StFstSlowSimMaker                              2 files, +615   (ours)
          Runs MC through the real FST reconstruction chain rather than smearing.
    StFstFastSimMaker: set meanRStrip/meanPhiStrip on simulated hits   (ours)
    Each of these needs its BFC option in the same PR -- see the note above wave 1.

  WAVE 5 -- the tracker core: decompose #826 along Daniel's own split
    He already separated this work in his fork as PRs #13-#19. Re-propose each as its
    own PR, in this order, each depending only on wave 2:
      #13 FST/FTT hit-finding and track-fitting fixes
      #14 seed-curvature fixes + FST warm-start refit
      #15 FTT diagonal-strip calibration gaps
      #16 DCA target/method in refitTrack
      #17 beamline position from DB
      #18 BLC-vertex and FCS-constrained track types     (needs wave 2)
      (#19 StFwdAlignmentMaker and wiring...needs #17, #18, see section 4 below)

    Two further fixes that belong with this wave rather than in a findings list:
      * FitterUtils: no reversed-field charge correction. The hits determine only the
        sign of q*Bz, so in a reversed field every seed charge guess is inverted and
        the fit does not fully recover. Measured on reversed-field single-electron MC
        at pT 0.5: 68.1% -> 76.1% correct charge.
      * FitterUtils: every collinear seed triple is logged at LOG_DEBUG and the seed
        pT at LOG_INFO; in dense MC that was ~660k lines per run.

  WAVE 6 -- remaining code fixes (ours)
    StFwdTrackMaker planar FTT chamber plane index
    StFstHitMaker global position                  (rebase on the merged #2)
    StFcsDb: gate the beamline read on mDbAccess. With setDbAccess(0) -- MC and
      particle-gun analysis -- the current code picks up a real, undated DB beamline
      record and corrupts getLorentzVector().

  WAVE 7 -- macros and BFC wiring last, written once against what landed
