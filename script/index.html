Overview

Three simulation/data passes all feed into one pico analysis chain.
Akio's working directory: /star/u/akio/fcstrk11/star-sw-fwd/

Base data directory: DataDisk/ -> /gpfs01/star/pwg_tasks/FwdCalib/akio
Setup: Create a symlink so all example commands work as written: 
ln -s /gpfs01/star/pwg_tasks/FwdCalib/[your user name] DataDisk

Particle Gun

GEANT single-particle events + BFC reconstruction.
Output: DataDisk/particle/{TYPE}/

Pythia MC

Pythia6 pp events + GEANT + BFC reconstruction.
Output: DataDisk/pythia/{TYPE}/

Real Data

FwdTracking+FCS afterburner on production MuDst files.
Output: DataDisk/pico/

Pico Analysis

Track–cluster matching + dilepton analysis on picoDst.
Output: DataDisk/{OUTDIR}/hist_match/, DataDisk/{OUTDIR}/hist_dilep/

Scripts detect the sample type from the type= value: type=data → real data  |  type=pythia.* → Pythia MC  |  anything else → particle gun.

Single Particle Gun

Step 1 — Submit simulation (GEANT + BFC)

# Dry run (shows condor file only):
./script/submit_sim.pl type=ele.pt1.5.vz0 nev=1000 r1=1 r2=100

# Submit to condor:
./script/submit_sim.pl type=ele.pt1.5.vz0 nev=1000 r1=1 r2=100 submit

# Other examples:
./script/submit_sim.pl type=ele.e5.vz0     nev=1000 r1=1 r2=100 submit
./script/submit_sim.pl type=pos.pt2.0.vz10 nev=500  r1=1 r2=50  submit
./script/submit_sim.pl type=pion.pt1.0.vz0 nev=1000 r1=1 r2=100 submit

TYPE format: {pid}.pt{PT}.vz{VZ} or {pid}.e{E}.vz{VZ}
Output: DataDisk/particle/{TYPE}/*.{fzd,MuDst.root,picoDst.root}
Condor file: condor/submit_sim_{TYPE}.txt

Step 2 — Pico analysis

./script/find_pico.pl  type=ele.pt1.5.vz0
./script/submit_ana.pl type=ele.pt1.5.vz0 outdir=ele.pt1.5.vz0 submit
./script/merge_ana.pl  outdir=ele.pt1.5.vz0
root -b -q 'plotMatch.C("DataDisk/ele.pt1.5.vz0")'

Pythia MC

Step 1 — Submit simulation (Pythia6 + BFC)

./script/submit_sim.pl type=pythia.JPsi.vz0 nev=200 r1=1 r2=100 submit
./script/submit_sim.pl type=pythia.dy.vz0   nev=200 r1=1 r2=100 submit
./script/submit_sim.pl type=pythia.mb.vz0   nev=200 r1=1 r2=100 submit
./script/submit_sim.pl type=pythia.jet.vz0  nev=200 r1=1 r2=100 submit

TYPE format: pythia.{PROC}.vz{VZ}  —  PROC: JPsi dy mb jet dybg dybgSingle
Output: DataDisk/pythia/{TYPE}/

Step 2 — Pico analysis

./script/find_pico.pl  type=pythia.JPsi.vz0
./script/submit_ana.pl type=pythia.JPsi.vz0 outdir=pythia.JPsi.vz0 submit
./script/merge_ana.pl  outdir=pythia.JPsi.vz0
root -b -q 'plotDilep.C(-1,6,"DataDisk/pythia.JPsi.vz0",-1,1,4)'

Step 3 — High-statistics example (vz40, with missing-run recovery)

Realistic-vertex (σzvtx=40cm) J/ψ and Drell-Yan+background samples, run at much larger scale (dybg: 20000 runs — see Data Files). In batches this large a handful of condor jobs can get evicted/killed before finishing (low-acceptance filters like the J/ψ generator filter mean some runs need far more wall time than average to reach the target event count) — check for and resubmit any missing runs before cataloging.

# 1. Submit simulation
./script/submit_sim.pl type=pythia.JPsi.vz40 nev=200 r1=1 r2=200   submit
./script/submit_sim.pl type=pythia.dybg.vz40 nev=500 r1=1 r2=20000 submit

# 2. Check for/resubmit any runs that failed to produce a picoDst.root
./script/check_missing.pl type=pythia.JPsi.vz40 r1=1 r2=200   nev=200 resubmit
./script/check_missing.pl type=pythia.dybg.vz40 r1=1 r2=20000 nev=500 resubmit

# 3. Catalog picoDst output into list shards
./script/find_pico.pl type=pythia.JPsi.vz40
./script/find_pico.pl type=pythia.dybg.vz40

# 4. Submit pico analysis (picoMatch + picoDilepton)
./script/submit_ana.pl type=pythia.JPsi.vz40 outdir=pythia.JPsi.vz40 submit
./script/submit_ana.pl type=pythia.dybg.vz40 outdir=pythia.dybg.vz40 submit

# 5. Merge
./script/merge_ana.pl outdir=pythia.JPsi.vz40
./script/merge_ana.pl outdir=pythia.dybg.vz40

# 6. Plot
root -b -q 'plotDilep.C(-1,6,"DataDisk/pythia.JPsi.vz40",-1,1,4)'
root -b -q 'plotDilep.C(-1,6,"DataDisk/pythia.dybg.vz40",-1,1,4)'

Real Data Afterburner

Step 1 — Build MuDst file list

# prod_mudst.txt: one MuDst path per line (e.g. point at a GRID NFS file list,
# or generate manually)
ln -sf /star/data14/GRID/NFS_FileList/{your_file_list} prod_mudst.txt

Step 2 — Submit afterburner (MuDst → picoDst)

./script/submit_check.pl         # dry run: reports jobs queued/skipped
./script/submit_check.pl submit # submit to condor
# Output: DataDisk/pico/st_fwd_*.picoDst.root (skips files whose picoDst already exists)

Step 3 — Pico analysis

./script/find_pico.pl  type=data
./script/submit_ana.pl type=data outdir=202606 submit merge
root -b -q 'plotMatch.C("DataDisk/202606")'
root -b -q 'plotDilep.C(-1,6,"DataDisk/202606",-1,1,4)'

Pico Analysis — All Steps

Step A — Catalog pico files

./script/find_pico.pl type=ele.pt1.5.vz0   # → picolist/ele.pt1.5.vz0.{N}.list
./script/find_pico.pl type=pythia.JPsi.vz0 # → picolist/pythia.JPsi.vz0.{N}.list
./script/find_pico.pl type=data            # → picolist/{RUN}.{N}.lis + runs2.txt
# Option: maxfile=N  (default 100 pico files per job)

Step B — Submit analysis

# option=11: bit0=picoMatch  bit1=picoDilepton  (both enabled)
./script/submit_ana.pl type=ele.pt1.5.vz0   outdir=ele.pt1.5.vz0   submit
./script/submit_ana.pl type=pythia.JPsi.vz0 outdir=pythia.JPsi.vz0 submit
./script/submit_ana.pl type=data             outdir=202606           submit
# Append 'merge' to also run merge_ana.pl when jobs finish
./script/submit_ana.pl type=data outdir=202606 submit merge

Outputs: DataDisk/{OUTDIR}/hist_match/{run}.{N}.match.root and DataDisk/{OUTDIR}/hist_dilep/{run}.{N}.dilep.root

Step C — Merge

./script/merge_ana.pl outdir=202606
# → DataDisk/{OUTDIR}/hist_match/all.match.root  +  hist_dilep/all.dilep.root

Step D — Plot

# Merged (all files):
root -b -q 'plotMatch.C("DataDisk/202606")'
root -b -q 'plotDilep.C(-1,6,"DataDisk/202606",-1,1,4)'

# Single shard — data (run=23081004, shard=0):
root -b -q 'plotMatch.C("DataDisk/202606",23081004,0)'

# Single shard — particle/Pythia (run=1, shard=0):
root -b -q 'plotMatch.C("DataDisk/ele.pt1.5.vz0",1,0)'

plotDilep.C(plt,cut,data,run,log,trkType) — trkType selects which of the 6 track types (0=Global 1=Beamline 2=Primary 3=FwdVtx 4=BLCVtx 5=FCSTRK) to plot; default is 1=Beamline, but most of the dilepton mixed-event-background work uses 4=BLCVtx.

root -b -q 'pico3.C(1000,11,23081004,0)'
root -b -q 'pico3.C(1000,11,1,0)'

# Plotting

File Naming Conventions

TypePatternExample
Particle gun {pid}.pt{PT}.vz{VZ}.run{N}.{ext}
{pid}.e{E}.vz{VZ}.run{N}.{ext}		 ele.pt1.5.vz0.run1.picoDst.root
Pythia MC pythia.{proc}.vz{VZ}.run{N}.{ext} pythia.JPsi.vz0.run42.picoDst.root
Real data st_fwd_{RUNNUMBER}_raw_{SEQ}.{ext} st_fwd_23081004_raw_1000002.picoDst.root
Pico list (sim) picolist/{TYPE}.{N}.list picolist/pythia.JPsi.vz0.0.list
Pico list (data) picolist/{RUN}.{N}.lis picolist/23081004.0.lis
Match histo {run}.{N}.match.root 23081004.0.match.root  /  1.0.match.root
Dilep histo {run}.{N}.dilep.root 23081004.0.dilep.root  /  1.0.dilep.root

ext = fzd, MuDst.root, or picoDst.root. For particle/Pythia, run=1 in analysis; use TYPE as OUTDIR to keep outputs separate.

Script Reference

New scripts (script/)

ScriptPurposeKey argumentsSource
submit_sim.pl Submit simulation jobs (particle or Pythia) type= nev= r1= r2= [submit] view
check_missing.pl Check a submit_sim.pl run range for runs whose picoDst.root was never produced (jobs evicted/killed mid-run, common in large batches) and optionally resubmit just those runs type= r1= r2= [nev=] [resubmit] view
find_pico.pl Catalog picoDst files into list shards type= [maxfile=] view
submit_ana.pl Submit pico analysis for all types type= outdir= [option=] [submit|run|merge] view
submit_check.pl Submit real-data afterburner (MuDst → picoDst), skipping individual files whose picoDst already exists (resumable) -- optional align arg also runs StFwdAlignmentMaker [submit|submitmerge] view
merge_ana.pl Merge histograms with hadd outdir= [types=match,dilep] view
runsim csh: particle gun GEANT (runSimFlat.C) + BFC (sim.C) — called by submit_sim.pl NEV RUN PID SPEC VZ OUTDIR WORKDIR view
runpico_uni csh: pico analysis wrapper, all types (called by submit_ana.pl) TYPE RUN ISET OPTION WORKDIR OUTDIR view
running200.pl Polls condor_q until this user's job count drops to/below a threshold; called by submit_ana.pl and submit_check.pl after condor_submit to block until a batch finishes (no args, reads $ENV{'USER'}) view
findmudst.pl Builds/refreshes the raw production MuDst file list (writes runs.txt, backs up the previous one to runs.txt.old) that feeds prod_mudst.txt (edit $name glob at top for a different production path) view

Notes

Configuration: All new scripts have a === CONFIGURATION === block at the top (WORKDIR, DATADIR, CONTAINER path). Edit once when setting up for a different user or cluster.
  • Use the TYPE name as OUTDIR for particle/Pythia to keep 1.N.match.root outputs in separate directories.
  • fGeom.root geometry cache must be present in WORKDIR for afterburner jobs. Build with: root4star -b -q -l StRoot/StFwdTrackMaker/macro/build_geom.C
  • Monitor condor jobs: condor_q $USER
