FST/FTT Tracking-Detector Alignment Residuals — Real Data (afterburner)

  • Code : StRoot/StFwdResidualMaker
  • Macro : macro/mudst/fwd_afterburner_db.C (reads an existing production MuDst, reruns FST/FTT/FCS reconstruction and forward tracking in memory)
  • Plot macro : script/plotFwdResidual.C
  • Sample : st_fwd_23081015_raw_6000057.MuDst.root, 1500 events, ~15940 tracks per type (Global 15941/BLC 15940/BLCVtx 15940)
  • Method : same as the Pythia MC page — per-plane residual between the hit used in the fit and the track's fitted projection at that z (pulled toward the hit; misalignments underestimated)
  • Residual axis range : FST ±1 cm, FTT ±2.5 cm (FST RMS 0.03–0.05 cm, FTT RMS 0.6–1.2 cm)
  • Jump to: Plane Usage  |  Global  |  BLC  |  BLCVtx  |  Outlier summary (all sets)
  • Unbiased (hit-removed) residuals from StFwdAlignmentMaker are the current main analysis — see residual/index.html

Fixed: FST "disk0 bucketing" bug

  • Every real-data run used to show 100% of FST hits landing in "disk0" regardless of the physical disk crossed. Root cause/fix: debug/index.html Issue #27 — StFwdResidualMaker was reading a stale, on-disk muDst->muFwdTrackCollection() instead of this session's freshly-refit tracks. Now reads StEvent::fwdTrackCollection() directly (with a setUseMuDst(true) fallback for standalone MuDst analysis).
  • Result: FST disk usage went from 100%/0%/0% to 100%/100%/100%, and FST residual RMS is now 0.03–0.05 cm per disk instead of meaningless.
