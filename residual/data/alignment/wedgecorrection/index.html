FST Per-Wedge Phi Correction — Validation

  • What: a per-(disk, wedge) empirical phi offset, applied to FST hits at MuDst-load time, to absorb the 12-fold (30°) step pattern (candidate explanation: StFstHitMaker::Make() not applying a DB/survey alignment correction it computes — see translation test page for that discussion and its open caveats). Not a fix at the source — a downstream correction that absorbs the step pattern regardless of its actual cause.
  • Source data (correction derivation): DataDisk/pico/alignment/*.FwdAlignment_BLCVtx.root (track type: BLCVtx), 150 files, ~117M rows — same dataset as distributions.html.
  • Source data (validation, before/after): uncorrected from the same 150-file set above (15-file subset); corrected from DataDisk/wedgecorr_condor/*.FwdAlignment_BLCVtx.root (15 files, run 23081015, all reprocessed via condor with the phase-fixed correction, see code below).
  • Code: FstWedgeAligner in StRoot/StFwdTrackMaker/StFwdHitLoader.h/.cxx, applied in StFwdHitLoader::loadFstHitsFromMuDst(). Opt-in only (setApplyFstWedgeAlignment(true) on StFwdTrackMaker, wired through fwd_afterburner_db.C's applyFstWedgeAlignment argument) — off by default, not yet in routine production.
  • Derivation: mean r·Δφ per (disk, wedge) measured from the full 150-file BLCVtx alignment campaign (core cut |r·Δφ|<0.3 cm), converted to a phi offset. Script: script/computeWedgeCorrection.C.
  • Wedge binning: 12 wedges of 30° each, phase-aligned to the same boundary found empirically in the step pattern. Same wedge# covers the same φ range on all 3 disks — StFstConsts.h's kFstphiStart/kFstphiStop (the hardware wedge-to-phi mapping) are single 12-entry arrays with no per-disk variant, so this is true by construction of the detector, not just of our phi-binning choice. See the phi-range column in the table below.

Why the steps aren't fully eliminated

  • Checked whether the correction table itself shows cross-disk structure: disk0/disk2 correlation is essentially zero (Pearson r=+0.03) across the 12 wedges. disk0/disk1 and disk1/disk2 show moderate anti-correlation instead (r=-0.68, r=-0.72) — a real but less clean pattern than a single obvious systematic, not yet interpreted.
  • Most likely explanation for the residual (not fully understood yet): the correction is a single mean offset per (disk,wedge) derived from 150-file-averaged stats, applied uniformly across all events/tracks in a 15-file subset with its own statistical noise and possibly its own sub-wedge structure (see the straight-line segments noted on the translation test page) — a single flat per-wedge number can't capture structure finer than one wedge.
  • Not yet done: fitting a joint/coherent model across disks, iterating the correction, or a finer-than-per-wedge correction. See To do.
