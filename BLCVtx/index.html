Forward BLC-Derived Vertex (BLCVtx)

  • Code : /star/u/akio/fcstrk11/star-sw-fwd (branch: dev)
  • Single-particle MC, e- at pT=1.5 GeV, eta in [2.5,4.0], vz=0
  • Concept
    • BLC (BeamlineConstrained) tracks are constrained to the beam line (sigma_z ~ 100 cm), so z is essentially free.
    • When two or more BLC tracks come from the same vertex, their DCA-z values cluster near the true z. A weighted-mean fit of those DCA-z values gives a vertex point with sigma_z ~ a few cm.
    • Each BLC track is then refitted with that vertex point as an additional hit → BLCVtx track. This is the forward analogue of TPC: Global → Beamline → Primary(vertex).
    • Expected benefit: BLCVtx sigma(q/pT) should lie between BLC and Primary (MC truth vertex).
  • Algorithm (doBLCVertexFitting in FwdTracker.h)
    • Select good BLC tracks: convergedFully, nFitPoints ≥ 4, chi2/NDF < 10, |DCA-z| < 100 cm
    • Weighted mean z_vtx: w_i = nFitPoints; sigma_vtx = weighted RMS (floor 1 cm)
    • Outlier rejection: remove |z_i - z_vtx| > 3*sigma_vtx; iterate up to 3 times
    • Build FwdHit at (x_BL, y_BL, z_vtx) with sigma_xy=0.1 cm, sigma_z=sigma_vtx
    • For each BLC track: append hit, fitTrack, refitTrack → mTrackType = kBLCVertexConstrained (=4)
    • Falls back to sigma_vtx = 30 cm for single-track events (no multi-track vertex)
  • Track type encoding change (StFwdTrack.h, StPicoFwdTrack.h)
    • Old: pack6and2 — 6-bit vtxIndex, 2-bit trackType (max type=3, cannot hold 4)
    • New: pack5and3 — 5-bit vtxIndex, 3-bit trackType (max type=7, holds kBLCVertexConstrained=4)
    • kBLCVertexConstrained=4 added to StFwdTrackType and StPicoFwdTrackType enums
  • Results
    • Track counts (after quality cuts in picoMatch.C) and sigma(q/pT) = RMS of (q/pT_reco - q/pT_true) in GeV-1; z_vtx residual = (z_vtx^BLC - z_vtx^MC) where z_vtx^BLC is picoMatch's weighted-mean BLC DCA-z and z_vtx^MC is the MC truth vertex z.

    • Known issue — sigma(q/pT) and Zres RMS do NOT decrease as more tracks are added (opposite of expectation):
      • Expected: more BLC tracks → better vertex z determination → tighter BLCVtx constraint → smaller sigma(q/pT) and smaller Zres RMS.
      • Observed: both sigma(q/pT)BLCVtx and Zres RMS increase monotonically with Ne/evt (0.666, 0.653, 0.678, 0.733 GeV-1; 12.3, 13.8, 14.7, 15.6 cm).
      • Importantly, sigma(q/pT)Primary (which uses the MC truth vertex point — perfect vertex) also degrades (0.573, 0.588, 0.631, 0.705 GeV-1). This means the degradation is NOT specific to the BLC vertex quality but is a general tracking issue with higher track multiplicity — likely hit confusion or occupancy effects in the forward detectors.
      • A positive mean bias in z_vtx grows with Ne/evt (+0.03, +1.19, +3.12, +6.06 cm). This is a secondary concern: even if the bias were corrected, the RMS would still increase.
      • The sentinel (99,99,99) bias from failed genfit extrapolateToLine was fixed via DCA-XY < 10 cm filter; the remaining degradation is a different, multiplicity-driven effect.

  • BLC Vertex Storage in StEvent / MuDst / PicoDst (2026-06-29)

    Previously the BLC vertex z was computed inside doBLCVertexFitting() and used only for refitting — it was discarded after the event. These changes persist it as a proper vertex object accessible from all three data formats.

    • Design decision — PicoDst storage
      • There is exactly one BLC vertex per event (or none), so a TClonesArray would always hold 0 or 1 entries.
      • The existing pattern for “the one vertex” in PicoDst is scalar fields in StPicoEvent (e.g. mPrimaryVertexX/Y/Z), not a separate array.
      • BLC vertex is stored the same way: five new inline fields in StPicoEvent, keeping it cleanly separate from the TPC primary vertex and from the FwdVertex TClonesArray.
      • StPicoFwdVertex class is not modified (ClassDef stays at 1).
    • Layer 1 — StEvent: new flag bit
      • StRoot/StEvent/StEnumerations.h — kBLCVtxId appended after kFwdVtxId in StVertexId enum
      • StRoot/StEvent/StVertex.h — setBLCVertex() and isBLCVertex() added alongside setFwdVertex() / isFwdVtx()
    • Layer 2 — FwdTracker: expose BLC vertex per event
      • StRoot/StFwdTrackMaker/include/Tracker/FwdTracker.h —
        • New member int mBLCVtxNTracks = 0 alongside existing mBLCVtxPos / mBLCVtxHit
        • Reset mBLCVtxNTracks = 0 at top of doBLCVertexFitting() (per-event)
        • Assigned mBLCVtxNTracks = trkZs.size() after outlier-rejection loop (inlier count)
        • Public accessors: getBLCVtxPos(), getBLCVtxSigmaZ() (derived from mBLCVtxHit._covmat(2,2)), getBLCVtxNTracks()
    • Layer 3 — StFwdTrackMaker: emit BLC vertex to StEvent
      • StRoot/StFwdTrackMaker/StFwdTrackMaker.cxx — after the existing FwdVertex loop, adds one StPrimaryVertex when getBLCVtxNTracks() > 0:
        • Position from getBLCVtxPos()
        • Covariance: sigma_xy = 0.1 cm (beam spot), sigma_z from getBLCVtxSigmaZ()
        • nTracks from getBLCVtxNTracks()
        • setBLCVertex() flag set — distinguishes it from TPC and FwdVtx entries
    • Layer 4 — MuDst: automatic + accessor
      • StMuDstMaker copies all StPrimaryVertex entries — BLC vertex appears in muPrimaryVertex array at no extra cost; mFlag is already serialized.
      • StRoot/StMuDSTMaker/COMMON/StMuPrimaryVertex.h — isBLCVtx() added alongside isBeamConstrained()
    • Layer 5 — PicoDst: scalar fields in StPicoEvent
      • StRoot/StPicoEvent/StPicoEvent.h — five new data members after mZdcUnAttenuated[2]: mBLCVtxX, mBLCVtxY, mBLCVtxZ, mBLCVtxSigmaZ, mBLCVtxNTracks; getters blcVertex(), blcVertexSigmaZ(), blcVertexNTracks(); setters setBLCVertexPosition(), setBLCVertexSigmaZ(), setBLCVertexNTracks(); ClassDef bumped 8 → 9
      • StRoot/StPicoEvent/StPicoEvent.cxx — fields initialized to 0 in default constructor; copied in copy constructor
      • StRoot/StPicoDstMaker/StPicoDstMaker.cxx — at end of fillFwdTracks(), loops primary vertices looking for isBLCVertex(), fills the five StPicoEvent fields (breaks after first match since there is only one)
    • How to use in analysis
      • StEvent: StPrimaryVertex *v = ...; if(v->isBLCVertex()) ...
      • MuDst: StMuPrimaryVertex *v = ...; if(v->isBLCVtx()) ...
      • PicoDst: picoEvent->blcVertex().Z(), picoEvent->blcVertexSigmaZ(), picoEvent->blcVertexNTracks() — returns 0 in all fields if no BLC vertex found
      • Backward compatibility: old PicoDst files read by new code return 0 for all BLC fields (ROOT default for new members). New PicoDst files read by old code: old code simply ignores the new fields.

  • Beamline from DB for BLC Track and Vertex Fitting (2026-06-30)

    Previously the BLC beam-line constraint used a hardcoded line at x = y = 0 (fine for MC where truth particles originate on axis). For real data the measured RHIC beamline (stored in the STAR DB table Calibrations/rhic/vertexSeed) should be used instead. This adds an optional, run-level beamline update that is off by default (MC unchanged).

    • DB reading — StFcsDb (already existed, now enabled)
      • StFcsDbMaker/StFcsDb.cxx line 399: the call to beamline DB lookup (filling mVx, mVy, mVdxdz, mVdydz) was commented out; it is now enabled.
      • StFcsDbMaker/StFcsDb.h — four new inline public getters added after getLorentzVector(): getBeamlineX(), getBeamlineY(), getBeamlineDxDz(), getBeamlineDyDz(). No .cxx change needed — the members are already filled in InitRun().
    • Tracker update — FwdTracker.h
      • New method setBeamline(x0, y0, dxdz, dydz): updates mBeamlineHit.x/y and stores slopes in new private members mBeamlineDxDz, mBeamlineDyDz.
      • Slope correction applied in doBLCVertexFitting() Step 4: the BLC vertex point is now at (x0 + dx/dz · zvtx, y0 + dy/dz · zvtx, zvtx) instead of (x0, y0, zvtx).
      • Default slopes are 0.0, so MC behavior is unchanged even if setBeamline is called with slopes only.
    • Maker wiring — StFwdTrackMaker
      • StFwdTrackMaker.h — added InitRun(int runNumber) declaration and public setter setUseBeamlineFromDB(bool use=true); private flag mUseBeamlineFromDB = false.
      • StFwdTrackMaker.cxx — new InitRun() method: if flag is set, retrieves StFcsDb from chain and calls mForwardTracker->setBeamline(...) once per run. Beamline is run-level data — set in InitRun(), not per-event in Make(). Prints x0, y0, dxdz, dydz at LOG_INFO level.
    • Afterburner macro
      • StFwdTrackMaker/macro/mudst/fwd_afterburner_db.C — one line added in the fwdTrack setup block: 
        if (runDb) fwdTrack->setUseBeamlineFromDB( true ); // use measured beamline for BLC; off for MC
        No other macro changes needed. MC runs leave runDb=false and continue to use x = y = 0.
    • Validation — single-file real-data test (run 23081004, 2022-03-22 pp500)
      • Beamline values read from DB: x0 = −0.0803 cm, y0 = −0.2138 cm, dx/dz = −9.02 × 10−4, dy/dz = +3.33 × 10−4.
      • Offsets are ~1–2 mm and slopes are sub-mrad — physically sensible for the RHIC beam.
      • LOG_INFO line confirmed at chain init; tracking ran without errors.
