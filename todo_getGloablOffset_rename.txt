Why it is not done yet
----------------------

It touches files that four open PRs also touch, and a pure rename colliding
with real work is the worst kind of conflict to resolve: every hunk looks
identical and the merge tool cannot tell which side meant what. So it waits
until the PRs that touch those files are in.

GATE, as of 2026-11-10:

    #22  MERGED
    #23  MERGED  (with a real merge commit)
    #39  MERGED
    #47  OPEN    StFttClusterPointMaker -- touches StFttClusterPointMaker.cxx
    #49  PUSHED, open -- touches FwdGeomUtils.h, FwdTracker.h

So the gate is now just #47 and #49. When both land, do it.


How, when the gate opens
------------------------

One commit, nothing else in it, so the diff is reviewable at a glance:

    git grep -l getGloablOffset | xargs sed -i 's/getGloablOffset/getGlobalOffset/g'
    cons +StFttDbMaker +StFttClusterPointMaker +StFttPointMaker \
         +StFttSimMaker +StFwdTrackMaker

Check before pushing:

  - "git grep -c getGloablOffset" returns nothing.
  - The count of getGlobalOffset is 24, matching the table above. A different
    number means something else was renamed by accident.
  - All five packages build. StFwdTrackMaker is the one that breaks late,
    because it only sees the header change at dlopen.

NOT a behaviour change, and it must not be bundled with one. If the mm->cm
Tier 1 work (ftt_mm_cm.txt) happens around the same time, keep them separate:
that one changes what the function RETURNS, this one only what it is called,
and a reviewer should never have to tell them apart inside one diff.
