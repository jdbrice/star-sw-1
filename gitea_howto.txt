RECOMMENDATION: MAKE ~/fcstrk14, FRESH FROM THE GITEA FORK
-----------------------------------------------------------
Do not repoint fcstrk13 at Gitea. Its origin is the frozen GitHub repo and its main is a
GitHub snapshot; even if the histories match today it will drift from Gitea's main
without any obvious signal, and PRs would be built on a stale base. The ambiguity is the
cost, not the disk space.

Keep fcstrk13 as the GitHub-era reference: it is where the fstMuRawHit work was built and
tested, and it still has the working build tree.

The decision is low-stakes anyway, because the work is three small patches -- see below.


SETUP
-----
    mkdir ~/fcstrk14 && cd ~/fcstrk14
    git clone --no-checkout git@git.racf.bnl.gov:akio/star-sw           
    cd star-sw
    git remote add upstream <gitea>/<star>/star-sw
    git fetch upstream

One branch per PR, always based on upstream/main:

    git checkout -b <topic> upstream/main
    git am ~/fcstrk13/patches/<patch>
    git push origin <topic>

Then open the PR in Gitea: akio/star-sw:<topic>  ->  <star>/star-sw:main


ACCESS: SOLVED -- HTTPS WITH YOUR SDCC PASSWORD (2026-09-30)
--------------------------------------------------------------
    cd ~/fcstrk14
    git clone --no-checkout --filter=blob:none \
        https://akio@git.racf.bnl.gov/gitea/akio/star-sw.git
    cd star-sw
    git remote add upstream https://akio@git.racf.bnl.gov/gitea/<ORG>/star-sw.git

Confirmed working: 188577 objects. Get <ORG> from the "forked from" line on your fork's
page rather than guessing.

The credential that works is your SDCC password, NOT a Gitea access token. This is the
part that cost an afternoon:

  - /gitea/<user>/<repo>.git/* is behind the SDCC proxy's own Basic auth
    (WWW-Authenticate realm "SDCC Server Login"), which wants SDCC credentials.
  - /gitea/api/v1/* is NOT behind it and takes a Gitea token happily.
  So a token that demonstrably works against /api/v1/user is rejected by git clone, which
  reads as "bad token" and sends you off debugging the wrong thing.

SSH does not work and cannot be made to: git.racf.bnl.gov resolves to
webproxy1.sdcc.bnl.gov (both 198.125.209.38 and the v6 address), a web proxy with nothing
on 22. Ports 22/2222/222/29418 all DROP rather than refuse, so "git clone git@..." hangs
for minutes instead of failing. Registering a key in Gitea changes nothing. No alternative
gitea/git hostname resolves from the starsub nodes.

If you want to avoid retyping the SDCC password, credential.helper "store" needs FULL
URLs in its file, one per line:
        https://akio:<sdcc-password>@git.racf.bnl.gov
  not a bare token or password -- with a bare string the helper matches nothing and git
  silently falls through to prompting, which again reads as a rejected credential.
  chmod 600 the file; it is plaintext.

Also useful: the Gitea API works with a token for everything except the git endpoints, so
branch creation, file edits and opening PRs can all be done over the API if a clone is
ever unavailable.


THE PATCHES  (~/fcstrk13/patches/, all based on 1ef9aaefdf)
------------------------------------------------------------
1. 0001-StFstHitMaker-meanPhiStrip-must-be-float-not-int.patch
   The one-line fix. int meanPhiStrip truncated the cluster's charge-weighted phi.
   0 of 125181 production hits carry a fractional phi; after the fix 15.4% do, with the
   hit count unchanged. No persistent-format change.
   NOTE: this CHANGES reconstructed hit positions (local[1]) -- a physics change.

2. 0001-StMuFstUtil-read-FST-raw-hits-back-from-the-MuDst.patch
   The MuDst -> StEvent reverse for FST raw hits, which never existed. Purely additive:
   no existing signature changes, no existing caller touched, cannot alter any current
   output.

3. 0002-StFstRawHitMaker-read-FST-raw-hits-from-a-MuDst-so-F.patch
   setMuDstInput()/readMuDst(), so StFstClusterMaker can re-cluster from a MuDst.
   Default off, production path untouched.

2 and 3 are one logical change and belong in one PR. 1 stands alone.


SUGGESTED PR ORDER
------------------
PR #1 : patches 2+3, the fstMuRawHit read-back.
        Purely additive, cannot change existing output, and it is what Jerome and Gene
        are waiting on. A first PR into a freshly transitioned repo that nobody can
        object to is worth something on its own.

PR #2 : patch 1, meanPhiStrip.
        Technically one line, but it moves reconstructed FST hit positions. Say so in the
        description, with the evidence: 0 of 125181 production hits have fractional phi,
        15.4% after, up to 0.96 strip (~0.22 deg, ~0.5 mm at the outer radius) discarded.

Rationale for that order: PR #1 is unarguable and unblocks someone else. Leading with a
physics change, however small, invites a slower review on a repo where nobody has
established a review rhythm yet.
