July to October: what the code work bought

The same 74 forward-stream files, processed with the old code (July) and the current code (October). The current chain matches about 40% more clusters per event — 1.44× north and 1.37× south — while the residual width is slightly narrower in dx and wider in dy. A width-only comparison misses the gain entirely, which is why the yield is shown first.

Track types differ between the two panels: the rate is measured on BLCVtx, which is what the forward stream can offer, and the width ratios come from the Primary-track reconciliation in tracking section 13. The dy term is the open item there.

The two forward-stream passes use exactly the same 74 input files. July ran them uncapped (674 938 events), October at 5000 per file (348 984), so October is the first part of each of the same files. cm, over |d|<30 cm. North and south are displaced in opposite directions in all three datasets, by about 2–3 cm. That antisymmetry is the signature of a relative y offset between the FCS clusters and the track projections, not of a rotation: north sits near φ=0 where the azimuthal direction is +y, south near φ=π where it is −y, so a common y shift appears with opposite sign in the two halves. A rotation about z would shift both the same way.

It is present in July as well as October and in zero field as well as the forward stream, so it is a standing offset rather than anything introduced by the recent code work — and it is the same size in both forward-stream passes. Worth fixing: it is a single number.

What the numbers say

  • The dR width is expected, and its centre is fine. fcsR*dPhi is 7–7.7 cm while dR is 10.5–14.4. FST strips run along R, so R is the poorly constrained coordinate; the TPC vertex fixes z to about a cm and helps ZF 22, BLC does not constrain z at all and BLCVtx only loosely, which is why dR is widest there. FTT would help with its x and y, but at the present efficiency only 1–2 FTT hits land on a track. After subtraction dR is centred near zero, so this is understood rather than a defect. It is not a shower-max depth error: that would make dR strictly proportional to r and identical in both datasets, and the measured r dependence is neither.
  • Zero field matches five times more cleanly. S/B is 0.39–0.51 for ZF 22 against 0.078–0.095 for the forward stream. In the forward stream roughly 90% of the raw histogram is combinatorial, so any number taken from it without background subtraction is meaningless.
  • HCAL matching has essentially no signal in either dataset: S/B 0.025–0.079, and after subtraction the content inside |d|<30 cm cancels — 10 to 12 negative bins with a negative sum as large as the positive one. The HCAL widths are therefore not quoted; the plots are shown for completeness only.
  • FTT time calibration is not the limit. Per-run fttDataWindow anchors now exist for 10 of the 11 forward-stream runs, up from 2, with 86–94% of the 384 VMM entries usable. Re-running the whole arm with them changes every panel by 2% or less — dx 0.99, dy 1.00, fcsR*dPhi 0.98–1.01, dR 0.99 — so the FTT timing is not what limits the FCS match. The one run left uncalibrated, 23081053, has a single MuDst that stopped at 14 events and keeps the global DB window on purpose.
