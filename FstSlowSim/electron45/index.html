45° single-electron sanity check — FST slow-sim chain

← StFstSlowSimMaker · FST real-data clusters · the original 45° test (FTT) · StFttSimHitMaker

Why repeat this

  • The closure test on the mother page measures residuals in aggregate over a mixed sample. That is blind to a whole-wedge mislabel that happens to preserve r and φ — exactly the class of error that has bitten the FST repeatedly.
  • A single isolated track with known kinematics gives a discrete check instead: every hit can be attributed unambiguously, so the reconstructed wedge index can be compared hit-by-hit against the wedge implied by that hit's own GEANT truth φ.
  • Same idea, and the same particle gun, as the 45° electron test that was originally written for the FTT geometry.

Setup

  • Single e− per event, 500 events. pT = 1.5 GeV, η = 2.5–4.0, φ = 45° ± 0.001 rad at the vertex. Generator: script/genElectron45.C.
  • Chain — the real reconstruction path, no fast sim: 
    fzin y2024 agml usexgeom sdt20220401 fstDb fstSlowSim fstRawHit fstCluster fstHit
     MakeEvent StEvent McEvent ReverseField bigbig
  • Note the DB timestamp. sim.C's usual sdt20211016 predates FST installation, so Geometry/fst/fstOnTpc has no entry and StFstDbMaker::Make() returns StFATAL, killing the chain on event 0.

One thing to get right before reading the plots

The generated φ is the φ at the vertex. The electron is charged and bends over the 150–180 cm out to the FST, so the arrival φ has real tails and hits land in several wedges — 8 or 9 per disk here. That is physics, not a defect: the GEANT truth (black, first QA panel) shows the identical spread. A naive "all hits must be in one wedge" test would fail for entirely the wrong reason.

So the wedge test below is per hit, against that hit's own truth φ.

The 0.12% wedge mismatch is 2 hits out of 1724, both consistent with a track arriving within a strip-width of a wedge boundary, where the truth φ and the assigned strip fall on opposite sides. A wedge-numbering error would give a large fraction, not 2 hits.

rΔφ RMS is 0.0378 cm here versus 0.084 cm in the mixed-sample closure test. The improvement is expected and is not a better detector: with one isolated track there is no truth-matching ambiguity, so the tail that inflated the mixed-sample number is simply absent.

On 1866 raw hits → 1724 hits. The 7.6% is not inefficiency in the maker. Raw hits that land on the same strip have their charge summed into one channel, and the cluster maker merges everything in one (sensor, phiStrip) cell into a single cluster regardless of r adjacency — so two GEANT hits in the same phi strip but different r strips become one hit, placed at the outer strip. That is the adjacency-free merge and the max-r rule operating, now visible in MC for the first time. 500 single-electron events give ~3.7 FST hits per event rather than 3, so there are secondaries to merge.

What this does and does not add

  • Does: confirms wedge numbering discretely and per hit, on a track whose truth is known independently; confirms the r quantization is the pitch and nothing wider; confirms φ is unbiased at the 0.006° level.
  • Does not: validate the strip formula itself. The maker inverts the same kFstphiStart/kFstrStart formula StFstHitMaker uses forward, so that part of the round trip remains a tautology — see the Limitations section on the mother page.
  • Does not: say anything about whether the geometry xml matches the real detector. MC is generated from the xml.
  • Run with the StFstHitMaker consumer fix applied (still uncommitted). Without it every position here would be nonsense, as it was on the first run.
